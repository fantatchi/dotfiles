# 複数 writer 書込みプロトコル（multi-writer protocol）

Claude・Codex など複数のエージェント（および Obsidian モバイル等の外部ツール）が**同じ正本ファイルを更新する**環境での共通書込み規約。shared/ の葉ノード SSOT であり、各 writer スキルはここを参照し、自ファイル固有の適用点（どのセクションを編集するか・何を検証するか）だけを自身の SKILL.md に持つ（本プロトコルの再記述はしない）。

## 対象ファイル

単一の正本を全 writer で共有する。writer ごとのコピー（`.codex/context.md` 等）は作らない。

- `{project-root}/.claude/context.md`（writer: context-save, session-review Phase 4）
- `{project-root}/.claude/progress.md`（writer: context-save 連携2）
- タスクストア tasks.md（writer: gtd-add / gtd-done / context-save 連携1 / Obsidian モバイル。場所は resolver `task_store`、フォーマットは `tasks-format.md` が SSOT）

Codex 等の外部エージェントも同じファイルを更新する writer として扱う。「相手が Claude 形式で書いている」ことを前提にしない。

## 6 原則

1. **既存内容を保持する**
2. **最小範囲だけ変更する**
3. **書込み直前に再読込する**
4. **競合を検出したら停止する**
5. **書込み後に検証する**
6. **不明な内容は削除しない**

## 共通書込みプロトコル（MUST）

1. **初回読取り**: 対象ファイルを Read し、この内容を編集の基準にする
2. **最小 Edit の構成**: 変更を既知セクション単位の Edit（一意な anchor 文字列による部分置換）として構成する。ファイル全体の Write（テンプレートからの再生成）は**ファイルが存在しない新規作成時のみ**許可
3. **書込み直前の再読込**: Edit 適用の直前に対象ファイルを再 Read する
4. **競合検出**: 初回読取りと再読込の内容に差分がある場合、別プロセスまたは他 writer が更新した可能性がある
   - 差分が自分の編集対象範囲と**重ならない** → 最新内容を基準に Edit を組み直して続行（他 writer の変更を保持したままマージ）
   - 差分が編集対象範囲と**重なる・安全にマージできるか判断できない** → 自動書込みを**停止**し、双方の差分を提示してユーザーに競合を報告する
5. **適用**: Edit を実行する
6. **書込み後検証**: 再 Read し、①編集箇所が意図どおりか ②見出し集合・frontmatter キー集合が編集意図以外で減っていないか を確認する。各ファイル固有の検証項目（tasks.md のセクション数・文字数上限等）は各スキル / tasks-format.md 側の規定に従う

古いスナップショット（初回読取り時の内容）を根拠にファイル全体を上書きすることは、いかなる場合も禁止。

## 未知内容の扱い

- 未知の frontmatter キー・見出し・フィールド・本文は**エラーにせず有効データとして無条件保持**する（削除・並び替えをしない）
- 他 writer が書いた有効な内容を、**文体の正規化だけを目的に書き換えない**（「Claude らしい文章」への書き直し禁止。内容が事実として陳腐化した場合の更新は通常の編集として可）
- `updated_by: claude` のような **writer 識別の必須フィールドを追加しない**。既存の共通フィールド（`updated` 日時等）の更新は従来どおり

## lossy 処理（情報を失う処理）の区別

ローテーション・圧縮・セクション削除など情報を失う処理は、各スキルが自身の SKILL.md で「lossy 処理」として**明示列挙したものだけ**実行してよい。その場合も:

- 対象は**既知フォーマットに一致した entry のみ**（日付プレフィックス・完了マーカー等がパースできるもの）
- パースできない entry・他 writer 由来とみられる形式不明の entry は**保守的に残す**（誤削除より誤残存を選ぶ）
- lossy 処理の実行は通常更新と区別して報告する（何件削除/圧縮したか）
