# ELI5（図解 HTML）

`$ARGUMENTS` を、**何も知らない人向けの図解ページ 1 枚**にして返す。

## 狙い

やることは「わかりやすい解説文を書く」ではなく、**「図解ページを 1 枚ビルドする」**である。大きな図と少ない言葉という制約を課すと、前置き・注釈・言い換えを削って概念の骨格だけを組み立てざるを得なくなる。したがって **ターミナルに解説文を流さない**。説明は生成した HTML の中だけに置き、応答は 1〜2 行とファイルパスで終える。

## Step 1: 対象を解決する

**リポジトリ内のコード**のとき: 実物を読んでから描く。「よくある認証フロー」の一般論を出すくらいなら、**範囲を絞る提案をしてから**描く（例:「`src/auth/` 全体は広いので、ログイン成功までの経路に絞ります」）。

**一般概念**のとき: バージョン依存の挙動・API の具体が要るときだけ `WebSearch` / `WebFetch`、ライブラリなら context7 で裏取りし、**裏取りできなかった箇所は図中に「未確認」と明示する**。

## Step 2: 骨格を設計する

図にするブロックを **3〜7 個**に削る。**何を捨てるかを決めるのがこの工程の本体**であり、削れないなら対象が広すぎるので分割を提案する。

- 各ブロックは「登場するもの」か「起きること」のどちらか一方にする
- ブロック間の関係（順序 / 包含 / 分岐 / データの流れ）を 1 種類に決める。複数の関係を 1 枚に重ねない
- 読み手が最初に知りたい 1 文（この図で何がわかるか）を決め、ページ最上部の見出しにする

## Step 3: HTML を書く

以下は eli5 独自の規範で、`spec-writer/references/` は参照しない（学習用の使い捨てに DADS 準拠は過剰なため。この判断は意図的）。

- **1 ファイル完結**。CSS と SVG はインライン、**外部リソース参照をゼロにする**（CDN・Web フォント・画像 URL は使わない。オフラインで壊れるうえ、業務内容が外部へ出る経路になる）
- **文字量の上限**: 1 ブロック 30 字以内、ページ全体で 300 字程度。超えたら図の分解が足りていない
- **図は inline SVG と CSS Grid で描く**。箱・矢印・アイコンで関係を示し、その関係を文で書き直さない
- **色は背景 + 3〜4 色まで**。意味の区別にだけ使い、装飾に使わない
- **文字を大きく**: 見出し 32px 以上、ブロックのラベル 16px 以上
- JavaScript は任意（ステップ送り・タブ）。**無くても意味が通ること**を条件にする
- `prefers-color-scheme` によるダークモード対応は任意

## Step 4: 保存してブラウザで開く

1. `date +%Y%m%d-%H%M` でタイムスタンプを取る
2. 既定の保存先は**セッションの scratchpad ディレクトリ**（使い捨て前提）。ファイル名は `eli5-<slug>-YYYYMMDD-HHmm.html`
3. 「残して」「後で見たい」と言われたときは、プロジェクトの `.claude/eli5/` を提案し、**パスを提示してから**書く（`git rev-parse --show-toplevel` でルートを取得。git 管理外なら CWD）
4. ブラウザで開く。**コマンドは `&&` で繋がず個別に実行する**（チェーンすると permission パターンにマッチしない）
   - 第一候補: `wslview <path>`
   - 失敗したら: `wslpath -w <path>` で Windows パスへ変換し、`explorer.exe "<変換後>"`
   - どちらも失敗したら、開かずにパスだけ報告する（起動失敗は成果物の失敗ではない）
5. 書き終えたら `grep -nE '(src|href)="https?://|@import' <path>` で**外部参照が 0 件**であることを確認する

## Step 5: 報告する

1〜2 行 + ファイルパスで終える。**図の内容をテキストで再説明しない**。裏取りできなかった箇所がある場合だけ、その 1 点を添える。段落が並ぶ HTML や、図の下の長い解説文は、制約を自分で外している失敗。
