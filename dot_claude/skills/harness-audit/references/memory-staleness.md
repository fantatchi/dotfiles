# Phase 2: memory の陳腐化

今いるプロジェクトの memory ディレクトリ（システム指示にある memory のパス。グローバル用は `~/.claude/projects/-home-at-kato/memory/`）を点検する。提案だけを出し、適用はユーザーの選択に従う。memory は git の管理外なので、自動では消さない。

## 観点

1. **索引と実ファイルの食い違い**
   - `MEMORY.md` の索引行が指すファイルが無い → 索引行を削除するか、ファイルを作り直す
   - 索引に載っていないファイルがある → 索引に足すか、ファイルを削除する
2. **参照先が消えている**: 本文に出てくる `~/.claude/...` などのパス、スクリプト名、スキル名、hook 名、設定キーを抜き出し、`ls` / `grep` で今もあるか確かめる。無ければ「更新」か「削除」を提案する（名前が変わっただけなら更新）
3. **正本との重複**: CLAUDE.md・`~/.claude/docs/`・スキル本文に同じ内容が書かれていれば、memory 側の削除を提案する（docs/skill-management.md の「同一事項の実体を両方に持たない」）。背景や経緯だけを補っている memory は重複ではない
4. **内容が古い**: 「〜は未確認」「暫定」「当面」など、期限付きの書き方をしたまま 3 か月以上経っているものは、今も正しいかを 1 行の問いとして提示する（判定はユーザーに任せる）

## 出し方

1 ファイル 1 行で `<ファイル名>: <何が古いか> → <提案（削除 / 更新 / 索引修正）>` と書く。根拠（見つからなかったパス、重複先のファイルと行）を括弧で添える。問題が無ければ「Phase 2 → 指摘なし（N ファイル点検）」とする。

## 適用時

- 削除は `rm` の前に本文を表示し、選ばれたものだけ消す。`MEMORY.md` の索引行も同時に消す
- 更新は該当行だけを Edit する
